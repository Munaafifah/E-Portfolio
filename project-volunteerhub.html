VolunteerHub: uniting organizations and volunteers around activities that actually fill up correctly.

A volunteer activity registration system built on a layered Spring Boot API and a React frontend, designed around one core problem: keeping registrations accurate when capacity, deadlines, and duplicate sign-ups are all in play.

View Live Demo

The problem

What was missing

  • Organizations had no simple way to post volunteer activities for people to discover.
  • Volunteers needed an easy way to browse, filter, and join activities without back-and-forth.
  • Nothing stopped a volunteer from registering twice for the same activity.
  • Activities could silently overfill past their intended capacity.
  • Admins had no clear view of who had actually signed up.

Scope — two roles

  • Volunteer: browse activities, search and filter, register, cancel a registration, view their own sign-ups.
  • Admin: full CRUD over activities, visibility into all registrations across the platform, and access to reporting.

Why a layered backend

  • Keeps things organized: controllers only handle HTTP, services only handle rules, repositories only handle data.
  • Easier to test and fix — each layer can be checked in isolation before wiring the next one in.
  • Matches the standard Spring Boot convention, so the codebase is easy for another developer to pick up.

Business rules

No duplicate registration

A user can't register twice for the same activity.

Deadline check

Registration is blocked once the activity's registration deadline has passed.

Capacity check

Once an activity hits its capacity, no further registrations are accepted.

Save & increment

Once all checks pass, the registration is saved and the activity's registered count is incremented by one — keeping counts and reality in sync.

Reporting with MongoDB aggregation

"Most popular activities" pipeline

  • $match — keep only registrations with status "REGISTERED", ignoring cancelled ones.
  • $group — group by activity and count how many registrations each one has.
  • $sort — order activities from most to least registrations.
  • $limit — keep only the top N, e.g. the top 5.
  • $lookup — join in each activity's details (title, category) so the report shows real names instead of raw IDs.
