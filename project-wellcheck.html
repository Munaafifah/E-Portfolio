Case Study · Healthcare

WellCheck: bridging Malaysia's rural–urban healthcare gap with sensors, sync, and AI.

A cross-platform health monitoring system pairing a Spring Boot web app and a Flutter mobile app on a shared MongoDB Atlas database, built around real-time Arduino sensor data and an AI-assisted disease prediction API.

View Live Demo Read the Paper (IJIC)

The problem

Why existing platforms fall short

  • Rural residents in Malaysia travel an average of 43 minutes to reach a hospital, versus 28 minutes for urban residents — a gap that routine monitoring could close.
  • MySejahtera operates as a mobile-only app, locking out anyone who relies on a desktop.
  • MyHealth360 offers both web and mobile, but features are inconsistent across the two — a fragmented experience.
  • Neither platform captures real-time vital signs through sensors, or offers AI-assisted diagnostic support.

What WellCheck set out to do

  • Give patients one system, on any device, to track vitals and manage appointments.
  • Automatically capture heart rate, temperature, oxygen saturation, and ECG through wearable Arduino sensors.
  • Support five distinct roles — Patient, Doctor, Pharmacist, Clinic Assistant, Administrator — each with a tailored view.
  • Add an AI disease-prediction layer so providers get diagnostic support, not just raw numbers.

Why this shape

  • Web and mobile stay independent in framework (MVC vs. MVVM) but share one source of truth in MongoDB Atlas, so a doctor's update reaches the patient's phone without a separate sync layer.
  • Arduino hardware handles the sensing; a Node.js/Express layer exposes that data as a RESTful API to the mobile app.
  • The Django prediction API is kept separate from the core CRUD backend, so the AI model can be retrained or swapped without touching appointment or billing logic.
  • Stripe handles payment processing for consultations and prescriptions, consolidated into the same role-based system.

Methodology & validation

DSDM, four sprints

Development followed the Dynamic Systems Development Method across four iterative sprints — user management, health monitoring, appointment management, and financial management — matching the academic semester timeline while keeping stakeholder feedback continuous.

Black-box testing

17 test cases across five modules (User, Health Monitoring, Appointment, Financial, Sensor Management) were run without reference to internal code structure. All 17 returned a pass.

User Acceptance Testing

42 UAT cases were conducted with a real clinic stakeholder across all five user roles, confirming the system met real-world healthcare workflow expectations. All 42 passed.

Published research

The system and its evaluation are documented in a peer-reviewed paper in the International Journal of Innovative Computing (IJIC), co-authored with academic supervision.
